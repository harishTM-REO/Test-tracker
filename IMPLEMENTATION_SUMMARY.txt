PROBLEM SOLVED:
━━━━━━━━━━━━━━
Your Adobe Target Validation had inconsistent failure rates:
  • Run 1: 9 failed out of 68 (13% failure rate) ✅
  • Run 2: 32 failed out of 66 (48% failure rate) ❌ (3.7x worse!)

Root Cause: Browser pool degradation over time
  • Browsers accumulate stuck states
  • Timeouts cascade as pool degrades
  • Individual browser restarts don't clear pool-wide issues

═══════════════════════════════════════════════════════════════════════════════

SOLUTION IMPLEMENTED:
━━━━━━━━━━━━━━━━━━━━
"Simplest Starting Point" - Periodic Full Pool Refresh

Automatically clears and recreates the ENTIRE browser pool every:
  • 10 minutes (time-based threshold) OR
  • 200 URLs processed (workload-based threshold)
  → Whichever comes first

HOW TO DEPLOY (RAILWAY):

1. Open your AT 1.0 Worker service in Railway dashboard

2. Add these environment variables:

   POOL_REFRESH_AFTER_URLS = 200
   BROWSER_POOL_SIZE = 2
   MAX_PAGES_BEFORE_RESTART = 40
   ADOBE_VALIDATION_CONCURRENT = 2
   ADOBE_VALIDATION_MAX_PAGES_BEFORE_RESTART = 40

4. Test with a small dataset (50-100 URLs)
   → Watch logs for pool refresh messages

5. Test with full dataset (1000+ URLs)
   → Run TWICE and compare failure rates
   → Should be consistent now!

TUNING GUIDE:
━━━━━━━━━━━━━

If you still see many timeouts:
  → DECREASE thresholds (refresh more often)
     POOL_REFRESH_AFTER_MINUTES = 5
     POOL_REFRESH_AFTER_URLS = 100

If refreshing too often (overhead too high):
  → INCREASE thresholds (refresh less often)
     POOL_REFRESH_AFTER_MINUTES = 15
     POOL_REFRESH_AFTER_URLS = 300
